If that seq was compacted away, or this client's buffer overflowed (slow reader), the server sends `event: stream.reset` with {snapshotSeq, reason},
then `snapshot.*` frames ending with `snapshot.end`, then live events from snapshotSeq+1. Handle both reasons the same way: drop local state, apply the snapshot.

## Event envelope

Every SSE event and replayed event has this shape. `seq` is persisted per scope in the same transaction as the event write, so it is a stable resume cursor across daemon restarts; `(entity, entitySeq)` is the exactly-once dedupe key. Today's upper-case types map to dotted names (`AGENT_SPAWNED` → `agent.spawned`); the CLI's `capcomd.v1` output is unchanged.

## Agent activity

Agent activity: `?activity=1` on a run stream (with or without `feed=lifecycle`) adds `agent.activity_changed` frames: what each agent is doing now, the line in Agent.activity.
They are ephemeral (`durability: "ephemeral"`): sent only live, never replayed, not in GET /v1/runs/{runId}/lifecycle or /v1/events, and their SSE frames carry no `id:`, so they never move the Last-Event-ID cursor.
Their envelope `seq` is the last durable seq at the time (not a cursor), `entitySeq` is 0 and `id` is unique per frame; the latest frame per agent wins.
Coalesced: at most one per agent per second, and only when the line changes. On connect, snapshot.agents carries the current activity; after a resume without a snapshot, each agent's current activity is sent once right away.
Why opt-in on the run stream: the lifecycle feed stays state changes only for clients that don't ask, the daemon stream stays one frame per run, and a client that follows a run's lifecycle gets the line on the same connection.

## Agent workspace

`Agent.workspace` (`agents.tree`, `snapshot.agents`) and `agent.spawned` `data.workspace` say where an agent works, so a client can show a folder chip per agent and a run's distinct folders.
Show `label` verbatim: the sub-folder (`path`, e.g. `ids/v1`) when the agent is scoped to one, else the repository's base name (`matchkey`). Group by `repo` + `path` for distinct folders.
Today every agent works at the root of its run's repository (the one `capcomd run new` recorded, else the engine's `CAPCOMD_REPO`), so `repo` equals the run's repository without credentials and `path` is null.
`workspace` is null when the run has no repository. It is fixed when the agent is spawned; agents spawned by older daemons report the run's repository, and their `agent.spawned` events have no `workspace`.

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "properties": {
    "repo": {
      "type": "string",
      "description": "Repository the agent works in: absolute path or remote URL, without credentials. Today always the run's repository"
    },
    "path": {
      "description": "Sub-folder of `repo` the agent is scoped to, relative, '/'-separated; null = the whole repository (always null today)",
      "type": [
        "string",
        "null"
      ]
    },
    "label": {
      "type": "string",
      "minLength": 1,
      "description": "Short display name, show it verbatim: `path` when set (e.g. \"ids/v1\"), else the repository's base name without .git (e.g. \"matchkey\")"
    }
  },
  "required": [
    "repo",
    "path",
    "label"
  ],
  "additionalProperties": {},
  "description": "Where the agent works; null when its run has no repository. Absent on agent.spawned events written by older daemons"
}
```
