Crew · notes and open choices

A profile drawn as a crew member, not a settings form: who it is, what it knows, how it works, what it has done, where it comes from. Settings rows appear only in Edit.

Chosen: A

  • The roster beside the pane, by project, rows named by each profile's own name. B (the grid) was dropped.

Served by the daemon today: no server work

  • GET /v1/profiles (per project with repo): title, description, the daemon's does and fit sentences, tags, provider, model, effort, cost, tool mode, who it leads, whether it reports, readiness, skills with trust, an untrusted persona or sandbox file, version, layer, and the chain of files that made it.
  • GET/PUT /v1/profiles/{name}: every value as a typed row with the file that sets it. That is the page's live controls (board 3), including the conflict when the file changed underneath.
  • profile.changed on the daemon stream keeps the page live. GET /v1/run-options planners is the driver menu (board 6).
  • By project: GET /v1/profiles?repo= per project the app knows, plus the user layer once as "All projects".

Needs daemon work (ADR-024 lists most as not built)

  • One face per profile: the avatar seed on GET /v1/profiles rows and agent.spawned, so its agents wear the profile's bot everywhere. Small.
  • Recent work: a per-profile query over agents (counts this week and the last few, with outcome). Medium. Without it the section is left out, not faked.
  • Trust from the app: a route that trusts the hashes shown, as capcomd profiles trust does. The diff needs the text you last trusted; today only its hash is kept. Medium.
  • New, Remove, Install: PUT of a new name (with extends), DELETE, POST /v1/profiles/install with a preview before copying. The CLI has all three; the routes wait for a client.
  • SOUL.md inline: a route that reads and writes a profile's persona text. Today the API never serves prompt text (by design), and a project's persona edited here must be trusted again, as any change to it is. Medium.
  • Save to (board 3): PUT writes the profile's own file today; writing a project's override.yaml instead is new.

Open choices (yours)

  • Roster: decided, by project, with "All projects" last for yours that apply everywhere.
  • Recent work on the page, or leave history to History when it exists?
  • Needs you: a changed skill shows amber on Crew always, and counts in Needs you only while a run waits on it (drawn). Or count it always?
  • Crew's shortcut: ⌘1–9 open projects and ⌘0 is Home. ⇧⌘C, or none?

How it would ship
